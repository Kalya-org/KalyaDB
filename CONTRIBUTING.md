# Contributing to KalyaDB

KalyaDB is in its early planning stage. Contributions should help make the design clearer, safer, or easier to test.

## Before making a change

1. Check the README and relevant documentation.
2. Open or review an issue describing the problem or proposed improvement.
3. For major design changes, discuss the proposal before implementing it.

## Development expectations

- Keep changes focused and explain why they are needed.
- Add tests for implemented behaviour.
- Never commit credentials, private keys, personal data, or real application databases.
- Update documentation when behaviour or architecture changes.
- Do not describe a planned feature as implemented.

## Pull requests

Include a concise summary, the reason for the change, how it was tested, and any known limitations. Small, reviewable pull requests are preferred.
