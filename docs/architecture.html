TECHNICAL DESIGN

Architecture

Proposal, not implementation. The engine has not been built yet. This page describes an initial design that may change.

Proposed components

  1. Public API — how applications open databases and request operations.
  2. Query layer — parsing, validation, and query planning.
  3. Execution layer — performs requested reads and writes.
  4. Storage engine — durable on-disk representation and persistence.
  5. Schema/catalog manager — tracks database structure and metadata.
  6. Index manager — maintains indexes for faster lookups.
  7. Transaction and recovery layer — defines atomicity, isolation, durability, and crash recovery.
  8. Backup and integrity tools — verification, export, backup, and restore.

Open engineering decisions

The implementation language, query syntax, storage layout, page size, indexing strategy, and concurrency model are still undecided. We should prototype and measure before choosing.

Integration target

The first intended integration is local use inside the Kalya desktop application. This GitHub Pages site only publishes documentation; it does not host a database service.
